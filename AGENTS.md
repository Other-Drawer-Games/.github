# Organisation profile contributor guidance

Before development or delivery work, resolve current `main` of
`Other-Drawer-Games/other-drawer-games` through authenticated GitHub access, then
read its [development practices](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/docs/development/README.md)
and relevant flow, engineering and review procedures at that revision. Record
the revision with evidence. If access fails, report the path and blocker and
continue independent work using available guidance.

For individual ticket writing/refinement, use the central
[work-item skill](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/.agents/skills/odg-work-item/SKILL.md),
including its check for existing coverage. For cross-ticket relevance, duplicates,
dependencies or delivery status, use the
[backlog-maintenance skill](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/.agents/skills/odg-backlog-maintenance/SKILL.md).
Keep procedures central and preserve explicit write authority and human decisions.

For public-facing copy or visuals, read the central
[design contract](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/DESIGN.md),
[experience philosophy](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/docs/DESIGN_EXPERIENCE_PHILOSOPHY.md)
and [experience-review skill](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/.agents/skills/odg-experience-review/SKILL.md).
Follow the [render, critique and recheck stage](https://github.com/Other-Drawer-Games/other-drawer-games/blob/main/docs/development/EXPERIENCE_REVIEW.md).
Read remote skills as task guidance; these links do not install native tools.
Publisher assets remain centrally approved; preserve their source and identity.

This repository has no application build. Check Markdown links, image references
and `git diff --check`. For profile presentation changes, inspect the rendered
GitHub Markdown at desktop and narrow widths and record screenshots, revision,
viewport, findings and confirmation in the PR. Plain contributor-process changes
may record UX review N/A with a reason. Missing rendering access is incomplete.
Preserve existing work, use a feature branch and stop at a reviewable PR. Humans
control merging and issue closure.
